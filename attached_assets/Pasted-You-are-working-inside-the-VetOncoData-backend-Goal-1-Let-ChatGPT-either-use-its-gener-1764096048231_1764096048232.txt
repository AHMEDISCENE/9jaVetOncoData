You are working inside the VetOncoData backend.

Goal:
1) Let ChatGPT either:
   - use its general veterinary knowledge, OR
   - answer ONLY from VetOncoData / guideline context (DB-only mode).
2) Add a `/api/ai/guidelines` endpoint that supports this toggle.

Context:
- AI is already integrated via a helper like:
  callChatGPT({ systemPrompt?, userMessage, context? })
- Stack: Node + Express + Postgres.
- No frontend changes in this step.

Tasks:

1. Extend the ChatGPT helper
- Find `callChatGPT` (or equivalent) and change its signature to accept an optional mode:

  type ChatMode = "general" | "db_only";

  callChatGPT({
    systemPrompt?,
    userMessage,
    context,
    mode = "general",
  }: {
    systemPrompt?: string;
    userMessage: string;
    context?: string;
    mode?: ChatMode;
  }): Promise<string>

- Inside callChatGPT, build the `messages` array differently based on `mode`:

  - If mode === "general":
    messages = [
      { role: "system", content: defaultSystemPrompt },   // allow general knowledge
      context ? { role: "system", content: "Context from VetOncoData/guidelines:\n" + context } : null,
      { role: "user", content: userMessage }
    ].filter(Boolean)

  - If mode === "db_only":
    messages = [
      { role: "system", content:
        "You must ANSWER ONLY using the context provided. " +
        "If the context does not contain enough information, say you do not know. " +
        "Do not use outside knowledge. This is not a substitute for professional veterinary judgement."
      },
      { role: "system", content: "Context:\n" + (context || "NO CONTEXT PROVIDED") },
      { role: "user", content: userMessage }
    ]

- Keep try/catch and error handling so a failed API call never crashes the server.

2. Stub for guideline context (for future RAG)
- Create a helper function, e.g. `getGuidelineContext(question: string): Promise<string>`.
- For now, just return an empty string or a short hard-coded note.
- Add a comment that later this will query an embeddings/vector store.

3. New endpoint: guidelines Q&A with toggle
- Add:

  POST /api/ai/guidelines

  Request body: { question: string; mode?: "general" | "db_only" }
  Response: { answer: string }

- Behaviour:
  - If `question` is missing/empty → return 400.
  - Read `mode` from body; default to "general" if not provided.
  - Call `getGuidelineContext(question)` to get `context` (for now may be empty string).
  - Build a short `systemPrompt`, e.g.:

    "You are a veterinary oncology knowledge assistant. 
     Be cautious, mention uncertainty when needed, and remind users this does not replace a veterinarian’s judgement."

  - Call:

    const answer = await callChatGPT({
      systemPrompt,
      userMessage: question,
      context,      // may be empty for now
      mode,         // "general" or "db_only"
    });

  - Wrap everything in try/catch:
    - On success: return { answer }.
    - On error: log it and return status 500 with { answer: "Sorry, I could not answer that right now." }.

Scope:
- Backend only.
- Do not change existing analytics endpoints, except if you later want to pass `mode` to them.
- No DB schema changes yet.
- This step just adds the mode toggle and the /api/ai/guidelines route.
